# DoneWitness v0.2.0 — The page says “Saved”. Did it save?

DoneWitness checks what an AI-built local web app actually does and leaves a
reviewable `PASS`, `FAIL`, or `UNKNOWN` receipt. No LLM, account, or hosted service
is required to run it.

This second release focuses on useful business checks and a lighter CLI.

## One plan. Three implementations.

The expense demo checks input validation, the exact total and form state, and
persistence after navigation. The same reviewed plan produces:

| Implementation | Input validation | Total & form | Persistence |
| --- | --- | --- | --- |
| Working | PASS | PASS | PASS |
| Wrong total | PASS | **FAIL** | PASS |
| Fake save | PASS | PASS | **FAIL** |

The app can say “Saved” while the persistence check still fails. These are controlled
faults in a browser-localStorage example, not a claim about all bugs or production databases.

## What's new

- **Four business assertions:** `assert_text`, `assert_value`, `assert_count`,
  and `assert_hidden`, explicitly selected with Plan v3.
- **Offline plan checks:** `donewitness validate --plan PATH` checks structure and
  digest before starting an application. Valid format does not mean a passing app.
- **Lighter startup:** median `--version` 420 → 120 ms and `--help` 416 → 130 ms
  on Windows/Python 3.14.3. Fifteen alternating fresh-process samples per command;
  this measures CLI startup only, not browser execution.
- **Reliable interruption receipts:** stopping during application startup now
  preserves an incomplete UNKNOWN receipt, including the early Docker startup path.
- **A shorter entry point:** concise quickstart, a runnable fault demo, and
  [Chinese documentation](https://github.com/Drippinblood333/DoneWitness/blob/v0.2.0/docs/README.zh-CN.md).

No runtime dependency was added. Existing Plan v2 files need no edits. Plan v1/v2
contracts and digests, receipt inspection, integrity checks, and exit codes remain
compatible; older clients reject new v3 plans.

## Try it

Use Python 3.12–3.14 in a virtual environment:

```console
python -m pip install donewitness==0.2.0
python -m playwright install chromium
git clone --depth 1 --branch v0.2.0 https://github.com/Drippinblood333/DoneWitness.git
cd DoneWitness
donewitness validate --plan examples/expenses.plan.json
donewitness verify --plan examples/expenses.plan.json --base-url http://127.0.0.1:8765 --run-dir .donewitness/expenses --app-command python examples/expenses_app.py
donewitness inspect --run-dir .donewitness/expenses
```

[Full quickstart](https://github.com/Drippinblood333/DoneWitness/blob/v0.2.0/README.md)
includes the broken-save command. Each run needs a fresh output directory.

## Evidence and scope

The implementation was tested with real Chromium, Linux Docker, Python 3.12–3.14
on Linux/Windows, and clean wheel/sdist installations. Read the
[verification record and raw benchmark](https://github.com/Drippinblood333/DoneWitness/blob/v0.2.0/docs/releases/v0.2.0-evidence.md)
for exact commits, results, and known limits. Release assets include SHA-256 checksums;
these provide download integrity, not cryptographic attestation.

A PASS covers the reviewed criteria only. DoneWitness remains a CLI for locally
runnable web apps; it does not independently discover every missing requirement.
