# v0.2.0 candidate evidence

This is a development evidence record, not publication evidence. The acceptance
criteria were recorded in [V0_2_PLAN.md](../V0_2_PLAN.md) before implementation.

## Baseline and method

- Public baseline: tag v0.1.0, commit `7107aa049f5ffbefaa9e1fcdf1552f974c967185`.
- Candidate branch: `codex/v0.2.0-small-and-useful`.
- Local environment: Windows 11 build 26100, Python 3.14.3, Playwright 1.63.0,
  Pydantic 2.13.4. No runtime dependency was added or minimum version increased.
- Tests were reviewed separately: the two unsupported-future-plan tests now use
  version 4 because version 3 is implemented. Only release-specific version/file
  expectations advance to 0.2.0. Existing v2 digest assertions and goldens remain.

## Startup measurements

Command: `python scripts/benchmark_cli.py --samples 15`. The script exports the
released source to a temporary directory and alternates baseline/current fresh
Python subprocesses using the same interpreter and installed dependencies. Two
warmups per variant/command are excluded. Measurements include interpreter startup;
they are **not** browser execution benchmarks or cold-disk-cache measurements.

| Command | v0.1.0 median | Candidate median | Reduction |
| --- | --- | --- | --- |
| `--version` | 419.958 ms | 119.672 ms | 71.50% |
| `--help` | 415.624 ms | 129.615 ms | 68.81% |

Raw samples are in [v0.2.0-startup.json](v0.2.0-startup.json). Performance depends
on machine load and platform; CI tests import boundaries, not timing thresholds.
Help/version do not load Pydantic/Playwright. Validate/inspect do not load Playwright.

## Gates in progress

- Ruff and strict mypy: passed locally after implementation.
- Plan/CLI/release-contract targeted tests: passed; full suite still required.
- Wheel and sdist: built; distribution content/metadata check passed.
- Both artifacts: independently clean-installed outside the checkout; `pip check`,
  import/entrypoint isolation, version/help, and v3 offline validation passed.
- Evidence/inspection/result-bridge/receipt tests: 90 passed, one existing
  Windows file-symlink capability skip. No evidence-integrity checks were relaxed.
- Real Chromium tests initially returned UNKNOWN because the matching managed
  browser was absent. Installing the matching browser is in progress; this is not
  a passing browser verification result.
- Browser-backed artifact smoke, complete tests, Linux/Docker/Python matrix, and hosted
  exact-commit CI: not yet completed for this candidate.
- Public tag, PyPI upload, and GitHub Release: not performed.

## Interpretation limits

The new expense app is a maintained browser-localStorage fixture with controlled
wrong-total/fake-save faults, not an externally adopted project or database test.
Its verdicts must be demonstrated before claiming that those faults are detected.
No speed claim applies to browser procedures, and no integrity check was removed
to obtain the CLI startup improvement.
